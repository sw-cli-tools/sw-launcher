# Survey: sw-cor24-forth

A clean-room DTC (Direct Threaded Code) Forth for the COR24 24-bit
RISC ISA. The top-level kernel is a hand-written 3020-line assembler
file (forth.s) loaded by `cor24-run --run forth.s`; no binary loads
or address patches are used. Three sibling subprojects
(forth-from-forth/, forth-in-forth/, forth-on-forthish/) each ship
their own `kernel.s` exploring how much of the Forth can be moved
out of asm into Forth itself; all share the same register/memory
model. UART is the only I/O channel: source text is fed via
`cor24-run -u` and ends without an explicit terminator. Heaps and
stacks are register-rooted, not file-loaded: RSP boots to address
0x0F0000 (decimal 983040), DSP is the COR24 hardware sp inited at
0xFEEC00, and the Forth dictionary HERE pointer starts at the
`dict_end:` label inside the assembled image.

## 2. Memory loads

| layer-name  | path                                | address                                | source                                                | rationale |
|-------------|-------------------------------------|----------------------------------------|-------------------------------------------------------|-----------|
| forth_kernel | forth.s                             | (cor24-run --run text base, default)   | hand-written assembler (forth.s:1-3020)               | the kernel image; cor24-run --run handles its placement |
| fff_kernel  | forth-from-forth/kernel.s           | (cor24-run --run text base, default)   | generated by scripts/build-kernel.sh from xcomp.fth + core/*.fth (build-kernel.sh:44-49) | self-bootstrapping kernel; full dict already linked into the image |
| fff_selftest | forth-from-forth/compiler/out/runtime-selftest.s | (cor24-run --run text base, default) | scaffold + emitted dict concatenation (test-kernel.sh:38-48) | smoke test for the cross-compiled runtime |
| fif_kernel  | forth-in-forth/kernel.s             | (cor24-run --run text base, default)   | hand-written; ~50 asm primitives (kernel.s:1-2763)    | smaller asm kernel; remaining words come from core/*.fth at boot |
| fof_kernel  | forth-on-forthish/kernel.s          | (cor24-run --run text base, default)   | hand-written; ~22 asm primitives (architecture.md:42-56) | minimal asm; everything else moved to Forth |

No `--load-binary` is used anywhere in this repo. All artifacts are
loaded as assembler source via `--run`, and cor24-run owns the text
base. Forth source lines (.fth) are not memory-loaded; they are
streamed as UART input -- see section 4.

## 3. Patches

None. No `--patch` argument appears in any script. All addresses
the kernel needs (RSP base, UART MMIO, HERE init, LATEST init) are
baked into forth.s/kernel.s as `la` immediates (forth.s:38, 44, 49,
51) or label-relative storage (`var_here_val`, `var_latest_val`,
`var_sp_base` at forth.s:2897-2906; mirror labels in subproject
kernels at forth-in-forth/kernel.s:2531-2549 and
forth-on-forthish/kernel.s:2534-2554).

## 4. UART payload structure

Construction is identical across all entry points: shell collects
`.fth` source text (and any preamble core/*.fth tiers) into a single
string, then passes it to `cor24-run -u "$INPUT"`.

- Top-level demos (demos/*.sh): `INPUT="$(cat examples/<demo>.fth)\n"`
  -- a literal trailing newline appended by the shell heredoc
  (demos/fib.sh:3-4 and siblings).
- demo.sh test cases (demo.sh:28): each check passes a single Forth
  line ending in `\n`, e.g. `'2 3 + .\n'`.
- forth-from-forth/scripts/build-kernel.sh:33-42: concatenates
  core/runtime.fth, core/minimal.fth, core/lowlevel.fth,
  core/midlevel.fth, core/highlevel.fth, compiler/xcomp.fth, then
  literal `COMPILE-RUNTIME\n`. Order matters -- the phase-3 REPL
  defines `:` and `;` part-way through runtime.fth and uses them
  for everything after.
- forth-{from,in,on}-forth REPL/demo/dump/see scripts: prepend
  core tiers in fixed order
  (runtime, minimal, lowlevel, midlevel, highlevel) before the
  user payload (e.g. forth-from-forth/scripts/demo.sh:11-18,
  repl.sh:9-13).

Terminator: there is no explicit EOT, NUL, or sentinel token. UART
input simply ends; the kernel keeps reading until KEY blocks for
the next byte and the cycle budget (`-n`) expires. `BYE` halts
cleanly inside the kernel (forth.s:2891-2892, `do_bye: bra do_bye`)
but is rarely emitted by drivers.

Escape-sequence restriction: cor24-run interprets backslash escapes
in `--uart-input`, so source files passed via the subproject
demo.sh scripts must not contain literal `\n`, `\r`, `\t`, or
`\xNN` (forth-in-forth/scripts/demo.sh:7-11; reg-rs golden test
`tf24a_no_bad_escapes.rgt`).

Marker scheme: dump.sh / see-demo.sh inject a visible marker line
(`61 EMIT 61 EMIT ... 10 EMIT` -- prints `========\n`) into the
UART input before DUMP-ALL, so awk/sed can crop the noisy core-load
" ok" prompts (dump.sh:13-19 across the three subprojects).
build-kernel.sh uses paired markers `!!BEGIN-KERNEL!!` /
`!!END-KERNEL!!` printed by the cross-compiler (build-kernel.sh:46).

## 5. Heaps and stacks

Register-rooted; nothing is loader-allocated.

- Data stack (DSP -> COR24 sp).
  - hardware push/pop in EBR (Embedded Block RAM); see forth.s:8.
  - sp inits at 0xFEEC00 (decimal 16706560), grows down 3 bytes per
    push (CLAUDE.md:64; docs/inspect-stack-impl.md:102).
  - snapshotted into `var_sp_base` at boot (forth.s:40-45) for
    underflow checks.

- Return stack (RSP -> r1).
  - `la r1, 983040` at _start, i.e. 0x0F0000 (forth.s:38; mirror in
    forth-from-forth/kernel.s:38, forth-in-forth/kernel.s:38,
    forth-on-forthish/kernel.s:38).
  - Grows down (forth.s:6, forth.s:70-71 `add r1, -3; sw r2, 0(r1)`).
  - SRAM-resident; no explicit upper bound documented beyond the
    base.

- HERE / dictionary growth (heap equivalent in Forth).
  - `var_here_val` cell holds the bump pointer
    (forth.s:2897-2898).
  - Initialized at boot to label `dict_end:` (forth.s:51-53,
    forth.s:3020). The image's tail label is the heap floor.
  - For forth-from-forth, init is `fff_full_core_dict_end`
    (forth-from-forth/kernel.s:53-55, label at line 3946) because
    the full core dict is already linked into the image.
  - Grows up; `,` advances by 3, `C,` by 1, `ALLOT n` by n
    (forth.s:751-753, 787-789, 822-824).

- LATEST -- `var_latest_val` cell (forth.s:2899-2900) initialized to
  the kernel's last header label (`entry_ver` in forth.s:50,
  `entry_bye` in forth-in-forth/kernel.s:48, `entry_quit_vector`
  in forth-on-forthish/kernel.s:48,
  `fff_full_entry_083_QUIT` in forth-from-forth/kernel.s:50).

- Other system cells in the same data block:
  `var_state_val` (compile flag), `var_base_val` initialized to 10,
  `var_sp_base`, plus `word_buffer:` for WORD's counted-string scratch
  (forth.s:2897-3007).

UART MMIO is not a heap region but is named here for completeness:
data 0xFF0100 (-65280), status 0xFF0101 (-65279), TX-busy bit 7,
RX-ready bit 0 (forth.s:11-12, CLAUDE.md:121-124).

## 6. Build artifacts vs vendored

Built locally:
- forth.s -- hand-maintained source; assembled in-place by
  `cor24-run --run forth.s` each invocation. No precompiled .bin
  artifact lives in the repo.
- forth-in-forth/kernel.s, forth-on-forthish/kernel.s --
  hand-maintained source, same in-place pattern.
- forth-from-forth/kernel.s -- generated. scripts/build-kernel.sh
  regenerates it by running the phase-3 REPL over core/*.fth +
  compiler/xcomp.fth and capturing the asm text emitted between
  `!!BEGIN-KERNEL!!` markers (build-kernel.sh:1-49). Output goes to
  forth-from-forth/compiler/out/runtime-dict.s. The committed
  forth-from-forth/kernel.s is the cached result so fresh clones
  don't have to rebuild (architecture.md:8-9).
- forth-from-forth/compiler/out/runtime-selftest.s -- generated by
  test-kernel.sh as scaffold + emitted dict (test-kernel.sh:38-48).
- core/*.fth -- hand-written Forth tiers
  (runtime/minimal/lowlevel/midlevel/highlevel) shipped per
  subproject; consumed both at run time (UART preamble) and at
  build time (cross-compiler input).

Vendored: none. There is no vendor/ directory. cor24-run is a host
prerequisite per README.md:14-16 and is built out-of-tree from
sw-embed/sw-cor24-emulator. sed-rs is also assumed on PATH
(README.md:16). reg-rs (regression test runner) is invoked via
`scripts/test.sh` (test.sh:4) and stores tests in ~/.local/reg-rs/
(CLAUDE.md:88-97), not in this repo.

Other generated files: forth-from-forth/compiler/out/ is a build
output directory; forth-from-forth/compiler/fforth.py is a Python
helper.

## 7. Known limits

- Cycle budgets (`-n`) range from 5e6 (top-level test/demo,
  selftest banner) up to 3e9 (subproject dump.sh). Mid-tier
  examples: loop/if-else 50e6, fib 40e6, fizzbuzz 200e6,
  forth-in-forth demo 400e6, forth-from/on-forth demo 800e6,
  see-demo 1e9, build-kernel 800e6, test-kernel 200e6.
- Wall-clock cap (`-t 60`): only forth-from-forth/build-kernel.sh
  and test-kernel.sh use it (build-kernel.sh:44, test-kernel.sh:53).
- Speed: every script uses `--speed 0` (host-fastest).
- Cell size 3 bytes / 24 bits (CLAUDE.md:62).
- Branch offset signed 8-bit, +/- 127 bytes (CLAUDE.md:60).
- Dict name length 6 bits in the flags byte -> 63-char cap;
  bit 7 = IMMEDIATE, bit 6 = HIDDEN (forth.s:30-31).
- Stack underflow check only; no documented overflow guard. DSP
  grows down from 0xFEEC00 (EBR), RSP grows down from 0x0F0000
  (SRAM), and HERE grows up from `dict_end:` toward RSP base --
  HERE-vs-RSP is the implicit squeeze point.
- UART input must not contain literal `\n\r\t\xNN` -- cor24-run
  pre-interprets them
  (forth-in-forth/scripts/demo.sh:7-11; reg-rs `tf24a_no_bad_escapes`).
- LED! has no software verification; demo.sh skips it (demo.sh:64)
  and only probes state via `--dump | grep "FF0000 LED"`
  (demo.sh:156-159).
- `BYE` halts via tight `bra do_bye` self-loop (forth.s:2891-2892);
  graceful stop relies on cycle-budget exhaustion.

## Schema gaps for this repo

The launcher TOML must add:

- `[[project.subproject]]` (or equivalent): root + three siblings
  each with their own `kernel.s`, preamble order, scripts.
- `kernel_artifact`: path passed to `--run`; schema must allow
  zero `--load-binary` entries (this repo has none).
- `uart_preamble`: ordered list of files concatenated before user
  input. forth-in-forth omits runtime.fth; the others include it
  (e.g. `["runtime","minimal","lowlevel","midlevel","highlevel"]`
  under each `core/`).
- `uart_terminator`: must accept "none" as a first-class value
  (this repo emits no EOT/sentinel).
- `uart_markers`: optional begin/end pair for stdout cropping --
  `!!BEGIN-KERNEL!!`/`!!END-KERNEL!!` (build flows) and the
  ASCII `========` marker (dump/see flows).
- `cycle_budget` per script profile (this repo uses ~8 distinct
  values from 5e6 to 3e9).
- `wall_clock_seconds` (`-t`): opt-in; only used by
  forth-from-forth build/test.
- `speed` per profile (always 0 here, schema should not hard-code).
- `mode` enum: `run`, `terminal+echo` (REPL bridge), `build`
  (capture stdout, strip markers, write file), `dump` (`--dump`
  + grep MMIO), `selftest`. All five appear here.
- `register_model`: hint for `r0=W r1=RSP r2=IP sp=DSP fp=scratch`
  -- needed by any debug-dump rendering.
- `stack_init`: per-stack base + growth direction. DSP=0xFEEC00
  down (hardware), RSP=0x0F0000 down (set by `la r1, 983040`),
  HERE=`dict_end:` up. Not derivable from the binary; must be
  declared.
- `generated_artifact` + `regen_script`:
  forth-from-forth/kernel.s is committed but rebuildable; the
  launcher should detect staleness.
- `host_tools`: per-project PATH requirements (cor24-run, sed-rs,
  reg-rs) rather than global ambient.
- `regression_runner`: tests delegate to `reg-rs run -p tf24a
  --parallel` with bodies stored in ~/.local/reg-rs/ -- schema
  must allow out-of-tree test execution.
